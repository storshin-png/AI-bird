# Техническое задание на MVP (Minimum Viable Product)

## 1. Цель MVP

Проверить гипотезу: **система на базе Edge AI + Cloud-пайплайна способна достоверно фиксировать видовой состав птиц на путях миграции и предоставлять данные для экологического комплаенса B2B-клиентам.**

**Срок разработки MVP:** 4 месяца.
**Команда:** 6 человек (см. `TEAM.md`).

---

## 2. Функциональные требования

### 2.1. Edge-устройство (Sensor MVP)
- Захват аудио: 44.1 кГц, 16 бит, моно, MEMS-микрофон.
- Duty cycle: 10 мин запись → 50 мин сон (настраивается).
- FFT + спектрограмма на устройстве.
- **NN1 (TinyML):** бинарная детекция «птица / не птица», размер модели ≤ 300 KB.
- При срабатывании NN1 — сохранение 5-секундного WAV на microSD.
- Передача по LoRaWAN: timestamp, battery voltage, флаг детекции, температура.
- Питание: LiFePO4 + солнечная панель 5Вт, автономность ≥ 7 дней в пасмурную погоду.
- Корпус: IP67, защита от грызунов.
- **Калибровочный модуль — ОПЦИОНАЛЬНО в MVP** (переносится в v1.1).

### 2.2. Cloud Pipeline
- Прием WAV через REST API (загрузка рейдовой группой).
- Прием телеметрии через MQTT.
- **NN2 (Source Separation):** очистка спектрограммы от фонового шума.
- **NN3 (Classification):** определение вида птицы (топ-50 видов региона пилота).
- **Open-Set Detector:** порог уверенности; при его недостижении — метка «Unknown».
- Запись результатов в PostGIS + TimescaleDB.
- Пакетная обработка: до 1000 WAV-файлов за сессию.

### 2.3. Web-платформа
- Карта с точками установки датчиков (статус, последние данные).
- Тепловая карта детекций по времени/виду.
- Фильтры: вид, дата, датчик.
- Дашборд состояния сети (battery, last seen, errors).
- Простой экспорт CSV по детекциям.

### 2.4. Пилотное развертывание
- **5 датчиков** на одном миграционном коридоре (согласованная локация с партнером-заповедником).
- Длительность пилота: **4 недели** непрерывной работы.
- Рейдовое обслуживание: 1 раз в 2 недели.

---

## 3. Нефункциональные требования

| Параметр | Требование MVP |
|----------|----------------|
| Точность NN1 (F1) | ≥ 0.90 на валидационной выборке |
| Точность NN3 (Top-5) | ≥ 0.80 на валидационной выборке |
| Ложные срабатывания NN1 | ≤ 10% на тестовом наборе «чистого шума» |
| Автономность датчика | ≥ 7 дней без солнца |
| Время обработки 1 WAV в облаке | ≤ 10 сек |
| Доступность веб-платформы | 95% (без SLA) |
| Стоимость BOM датчика | ≤ $150 |

---

## 4. Критерии успеха (Definition of Done)

MVP считается успешным, если выполнены **все** условия:

1. ✅ Изготовлено и протестировано ≥ 5 рабочих прототипов датчиков.
2. ✅ NN1 работает на ESP32-S3 с инференсом ≤ 200 мс на фрейм.
3. ✅ NN3 корректно классифицирует ≥ 30 видов птиц с Top-5 accuracy ≥ 0.80.
4. ✅ Open-Set Detector отбрасывает ≥ 70% звуков неизвестных видов (не присваивает ложный класс).
5. ✅ Пилотное развертывание прошло 4 недели без критических отказов железа.
6. ✅ Веб-платформа отображает реальные данные с 5 датчиков.
7. ✅ Получен **письменный отзыв** от 1 B2B-клиента (ветропарк / застройщик / недропользователь) о ценности данных для их задач.
8. ✅ Подписан **LOI (Letter of Intent)** или пилотный контракт с 1 B2B-клиентом.

## 5. Ограничения и допущения MVP

### Что НЕ входит в MVP
- ❌ Идентификация отдельных особей по голосу.
- ❌ NN2 на Edge-устройстве.
- ❌ Передача WAV в реальном времени по LTE/спутнику.
- ❌ Калибровочный модуль (переносится в v1.1).
- ❌ Поддержка более 50 видов птиц.
- ❌ Мобильное приложение.
- ❌ Сертификация для государственного экомониторинга.

### Допущения
- Пилотная локация имеет согласование с владельцем земли/ООПТ.
- Рейдовая группа доступна для обслуживания (партнер-заповедник или подрядчик).
- Датасеты Xeno-canto и Macaulay Library достаточны для обучения NN3 на 50 видов.
- B2B-клиент найден до начала пилота (через CEO).

## 6. Этапы разработки (спринты по 2 недели)

### Спринт 1–2 (Недели 1–4): Hardware + NN1
- **CTO:** Выбор компонентов, макетная плата, базовая прошивка (захват аудио + FFT).
- **ML-инженер:** Сбор датасета, обучение NN1 (TinyML), квантование.
- **Орнитолог:** Разметка датасета, выбор 50 видов для пилотного региона.
- **Backend:** Настройка MQTT-брокера, базовый API для телеметрии.

### Спринт 3–4 (Недели 5–8): NN3 + Cloud Pipeline
- **ML-инженер:** Обучение NN3 (ResNet/EfficientNet) на 50 видов, Open-Set Detector.
- **Backend:** Pipeline обработки WAV (NN2 → NN3), запись в PostGIS.
- **CTO:** Сборка 5 прототипов, корпус, полевые тесты на столе.
- **GIS-разработчик:** Базовая веб-карта с точками датчиков.

### Спринт 5–6 (Недели 9–12): Интеграция + Пилот
- **Вся команда:** Интеграция Edge → Cloud → Web.
- **Орнитолог + CTO:** Установка 5 датчиков на пилотной локации.
- **GIS-разработчик:** Тепловые карты, фильтры, дашборды.
- **CEO:** Презентация прототипа B2B-клиентам, сбор LOI.

### Спринт 7–8 (Недели 13–16): Пилот + Анализ
- **Орнитолог:** Валидация данных пилота, корректировка датасета.
- **ML-инженер:** Дообучение моделей на реальных полевых данных.
- **CTO:** Обслуживание датчиков, сбор SD-карт.
- **CEO:** Подготовка отчета для B2B-клиента, закрытие LOI в контракт.
- **Вся команда:** Ретроспектива, планирование v1.1.

## 7. Риски MVP и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| NN1 дает >10% ложных срабатываний | Высокая | Высокое | Ужесточение порога, аугментация датасета шумом |
| Не удалось согласовать пилотную локацию | Средняя | Критическое | Начать согласования в Спринте 1, иметь 2 резервные локации |
| Датчик не выдерживает 7 дней автономности | Средняя | Высокое | Уменьшение duty cycle, упрощение платы |
| NN3 не распознает виды из-за диалектов | Средняя | Среднее | Сбор локального датасета орнитологом в Спринте 1 |
| B2B-клиент не найден | Средняя | Критическое | CEO начинает продажи с Недели 1, не после пилота |
| Повреждение датчиков в поле | Средняя | Среднее | Резерв +1 датчик, страховка, скрытый монтаж |

## 8. Выход из MVP (Success Criteria для Seed-раунда)

После успешного MVP стартап готов к привлечению Seed-инвестиций со следующими артефактами:

1. **Рабочая технология:** 5+ датчиков в поле, точные данные.
2. **Первый клиент:** Подписанный контракт или LOI с B2B.
3. **Датасет:** Собственные полевые данные (не только open-source).
4. **Юнит-экономика:** Подтвержденная стоимость владения 1 датчиком в год.
5. **Дорожная карта v1.1:** Калибровочный модуль, LTE-передача, расширение до 200 видов.

**Цель Seed-раунда:** $500K–$1M на 18 месяцев → масштабирование до 50 датчиков, выход на 3 B2B-клиента, разработка v1.1.
