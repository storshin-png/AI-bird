## 2. Edge Layer — Акустический датчик

### Аппаратная часть
- **MCU/DSP:** ESP32-S3 (с векторным ускорителем) или STM32H7 с внешним NPU.
- **Микрофон:** MEMS-микрофон с широким диапазоном (20 Гц – 20 кГц), I2S-интерфейс.
- **Калибровочный модуль:** Миниатюрный пьезоизлучатель с эталонным тоном (1 кГц, 94 дБ SPL) — встроен в корпус, активируется раз в сутки для самопроверки АЧХ.
- **Питание:** LiFePO4 3.2В 6000 мАч + солнечная панель 5Вт + MPPT-контроллер.
- **Хранение:** microSD 32 ГБ (буфер на случай отсутствия связи).
- **Связь:** LoRaWAN-модуль (для служебной телеметрии) + опционально LTE-модуль для точек с покрытием.

### Программная часть (прошивка)
- **Duty cycle:** 10 минут «слушания» → 50 минут сна.
- **Пайплайн на устройстве:**
  1. Захват аудио (44.1 кГц, 16 бит, моно).
  2. FFT → спектрограмма (окно 1024, hop 512).
  3. **NN1 (TinyML, ~200 KB)** — бинарная детекция «птица / не птица».
  4. При срабатывании NN1 → сохранение 5-секундного WAV + метаданные (время, GPS, температура, уровень калибровочного тона).
  5. Передача лога по LoRaWAN (текстовый пакет: timestamp, species_probability, battery).
  6. WAV накапливается на SD до визита рейдовой группы.

### Ключевые решения
- **Отказ от NN2 на Edge** — слишком ресурсоемко.
- **Калибровка АЧХ** — сравнение записи эталонного тона с базовым профилем; при отклонении >3 дБ — флаг «требуется обслуживание».

## 3. Communication Layer

### Режимы передачи данных
| Режим | Условия | Что передается | Частота |
|-------|---------|----------------|---------|
| **LoRaWAN-only** | Нет LTE/интернета | Текстовые логи (100 байт/пакет) | Каждые 10 мин |
| **LTE fallback** | Есть покрытие | WAV + логи | По событию (после срабатывания NN1) |
| **Sneakernet** | Полная изоляция | Полная выгрузка SD | Раз в 2–4 недели рейдом |

### Протоколы
- **MQTT** для телеметрии и команд (калибровка, смена duty cycle).
- **HTTPS** для загрузки WAV-файлов.
- **Шифрование:** TLS 1.3, уникальные device-сертификаты.

## 4. Cloud Layer

### Ingestion
- **MQTT Broker** (EMQX / Mosquitto) — прием телеметрии.
- **API Gateway** (FastAPI) — прием WAV-файлов от рейдовых групп.
- **Object Storage** (S3-compatible) — сырые WAV и спектрограммы.

### Processing Pipeline
WAV → NN2 (Source Separation, GPU) → Очищенная спектрограмма
↓
NN3 (Classification, GPU)
↓
Open-Set Detector → "Unknown"
↓
Запись в PostGIS + TimescaleDB

- **Оркестрация:** Apache Airflow или Prefect для пакетной обработки.
- **Инференс:** NVIDIA Triton или TorchServe на GPU-инстансах (по требованию).
- **Fallback:** если NN2 ухудшает сигнал (оценивается по SNR), в NN3 подается оригинал.

### Storage
- **PostGIS** — геоданные датчиков, границы миграционных коридоров.
- **TimescaleDB** — временные ряды: детекции, погода, состояние устройств.
- **S3** — сырые аудиоархивы (холодное хранение через 6 месяцев).

## 5. Application Layer

### Web-платформа
- **Frontend:** React + Mapbox GL JS.
- **Слои карты:**
  - Точки установки датчиков (цвет = статус: OK / Low Battery / Calibration Drift).
  - Тепловая карта плотности вокализаций по часам/дням.
  - Маршруты миграции (агрегация по видам).
  - Фильтры по виду, дате, времени суток.
- **Дашборды:**
  - Операционный: состояние сети устройств.
  - Аналитический: видовое разнообразие, пиковые часы, тренды.
  - Комплаенс-отчеты: PDF/Excel для B2B-клиентов.

### API для внешних клиентов
- REST API: получение агрегированных данных по bounding box / периоду.
- Webhook-уведомления о детекции краснокнижных видов в зоне строительства.

## 6. Data Flow (сценарий)

1. Датчик в лесу фиксирует вокализацию → NN1 срабатывает.
2. WAV сохраняется на SD, короткий лог уходит по LoRaWAN.
3. Через 2 недели рейдовая группа забирает SD, подключает ноутбук с 4G.
4. WAV загружаются в облако через API.
5. Pipeline: NN2 → NN3 → запись в БД.
6. Веб-платформа обновляет карту миграции.
7. B2B-клиент получает отчет о наличии/отсутствии охраняемых видов на своей территории.

## 7. Ключевые технические решения и компромиссы

| Решение | Обоснование |
|---------|-------------|
| NN1 на Edge, NN2/NN3 в Cloud | Баланс энергопотребления и качества анализа |
| LoRaWAN + Sneakernet | Работа в условиях отсутствия связи на путях миграции |
| LiFePO4 вместо Li-ion | Стабильность при отрицательных температурах, безопасность |
| Калибровочный тон | Компенсация дрейфа АЧХ микрофона |
| Open-Set в NN3 | Избегание ложной классификации неизвестных видов |
| Пакетная обработка в облаке | Снижение стоимости GPU-инференса |
| Duty cycle 10/50 мин | Компромисс между полнотой данных и автономностью |
