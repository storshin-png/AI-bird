# Стратегия сбора и разметки данных

## 1. Общие принципы

Качество нейросетей NN1, NN2, NN3 на 80% определяется качеством и репрезентативностью данных. Стратегия строится на трех столпах:

1. **Репрезентативность** — данные должны покрывать реальные условия эксплуатации (регион, сезон, биотоп, время суток, погода).
2. **Баланс** — избегание перекоса по видам, классам шумов и условиям записи.
3. **Валидация** — обязательная проверка разметки орнитологом на каждом этапе.

**Ответственные:**
- **Орнитолог** — методология разметки, контроль качества, выбор локаций.
- **ML-инженер** — техническая организация пайплайна данных, аугментация, версионирование.
- **CEO** — договоренности с источниками данных (заповедники, научные фонды).

## 2. Источники данных

### 2.1. Open-source датасеты (база для pre-training)

| Источник | Объем | Особенности | Использование |
|----------|-------|-------------|---------------|
| **Xeno-canto** | 600k+ записей, 10k+ видов | Глобальное покрытие, любительские записи, разное качество | NN3 (pre-training), NN1 (позитивные примеры) |
| **Macaulay Library (Cornell)** | 250k+ аудио | Высокое качество, метаданные (гео, дата, оборудование) | NN3, NN2 (чистые сигналы) |
| **BirdCLEF (Kaggle)** | Готовые датасеты соревнований | Размечены по видам, есть baseline-решения | NN3 (валидация архитектуры) |
| **ESC-50 / UrbanSound8K** | Шумы окружающей среды | Город, транспорт, природа | NN1 (негативные примеры) |
| **FSD50K / AudioSet** | Крупные аудио-датасеты | Разнообразие классов | NN1 (негативные примеры) |

**Ограничения open-source:**
- Перекос по регионам (Европа/Сев. Америка >> Азия/Африка).
- Перекос по популярным видам (зяблик, синица >> редкие виды).
- Преобладание "чистых" записей (редко встречаются наложения шумов).
- Отсутствие сезонной и контекстной вариативности.

### 2.2. Собственные полевые данные (ключевой актив)

Сбор полевых данных — **критическая задача**, которая превращает стартап из "обертки над open-source" в владельца уникального датасета.

**Источники полевых данных:**
1. **Партнерство с заповедниками** — доступ к их архивам записей (AudioMoth, Song Meter) в обмен на аналитику.
2. **Пилотное развертывание MVP** — 5 датчиков × 4 недели = ~2000 часов аудио.
3. **Целевой сбор в Спринте 1** — орнитолог выезжает на пилотную локацию с референсным оборудованием (парabolic mic + профессиональный рекордер) для записи "эталонных" голосов местных видов.
4. **Коллаборации с birdwatching-сообществом** — сбор записей через eBird/Macaulay с указанием точного GPS и даты.

**Целевой объем полевых данных к концу MVP:**
- ≥ 500 часов записей с пилотной локации.
- ≥ 50 видов, присутствующих в регионе пилота.
- Покрытие разных биотопов (лес, поле, водно-болотные угодья).
- Покрытие разного времени суток (рассвет, день, ночь — для ночных миграций).
- Покрытие разной погоды (тихо, ветер, дождь).

## 3. Стратегия по нейросетям

### 3.1. NN1 — Детекция «птица / не птица» (Edge)

**Задача:** Бинарная классификация спектрограмм.

**Структура датасета:**
| Класс | Источники | Объем (целевой) |
|-------|-----------|-----------------|
| **Позитив (птица)** | Xeno-canto, Macaulay, полевые записи | 50k спектрограмм |
| **Негатив (шум)** | ESC-50, UrbanSound8K, полевые записи без птиц | 50k спектрограмм |

**Критически важные подклассы негатива (hard negatives):**
- Шелест листвы на ветру.
- Стрекотание насекомых (цикады, кузнечики) — спектрально похоже на птиц.
- Дождь, град.
- Шум транспорта (далекий/близкий).
- Голоса млекопитающих (лягушки, грызуны).
- Антропогенные звуки (пилы, моторы).

**Баланс:** 1:1 (позитив:негатив). При перекосе — oversampling миноритарного класса или focal loss.

**Разделение:**
- Train / Val / Test = 70% / 15% / 15%.
- **Важно:** Test set должен содержать **только полевые данные**, не виденные при обучении. Это честная оценка реальной точности.

### 3.2. NN2 — Source Separation (Cloud)

**Задача:** Выделение целевого голоса птицы из смеси.

**Проблема:** Нет парных данных (смесь + чистый сигнал) в дикой природе.

**Стратегия — синтетическое микширование:**
1. Берем чистый голос птицы из Xeno-canto/Macaulay.
2. Берем фоновый шум из полевых записей (участки без птиц) или из ESC-50.
3. Микшируем с разным SNR (Signal-to-Noise Ratio): от -10 дБ до +10 дБ.
4. Получаем пары: `(смесь, чистый_сигнал)` — вход и target для NN2.

**Структура датасета:**
- 100k синтетических смесей.
- Распределение SNR: равномерное, с акцентом на сложные случаи (0...-5 дБ).
- Разнообразие фонов: 20+ типов шума (дождь, ветер, насекомые, транспорт, хор других птиц).

**Domain gap mitigation (сокращение разрыва между синтетикой и реальностью):**
- Аугментация: добавление реверберации, имитация АЧХ дешевого MEMS-микрофона.
- Fine-tuning на реальных полевых записях, где орнитолог вручную вырезает "чистые" фрагменты (semi-supervised).

### 3.3. NN3 — Классификация видов + Open-Set (Cloud)

**Задача:** Определение вида (топ-50 для MVP) + отбрасывание неизвестных.

**Структура датасета:**
- **Known classes (50 видов региона пилота):**
  - ≥ 500 записей на вид (суммарно из open-source + полевых).
  - Баланс по регионам, сезонам, времени суток.
- **Unknown classes (для Open-Set training):**
  - 200+ видов, НЕ присутствующих в регионе пилота.
  - 50+ классов "мусорных" звуков (не птицы).
  - Используются как негативные примеры при обучении Open-Set Detector.

**Метод Open-Set:**
- Обучение с **Angular Softmax (ArcFace)** или **Outlier Exposure**.
- На инференсе: если максимальная вероятность < порога (настраивается на валидации) → метка "Unknown".
- Порог калибруется так, чтобы отбрасывать ≥ 70% неизвестных (критерий успеха MVP).

**Разделение:**
- Train / Val / Test = 70% / 15% / 15%.
- **Стратификация:** по виду, региону, сезону.
- Test set — только полевые данные.

## 4. Процесс разметки

### 4.1. Уровни разметки

| Уровень | Описание | Кто делает | Инструмент |
|---------|----------|------------|------------|
| **L1: Бинарная** | «Птица / Не птица» | Junior-разметчики (аутсорс) | Audacity + кастомный скрипт |
| **L2: Видовая** | Конкретный вид (из 50) | Орнитолог или trained annotator | Raven Pro / BirdNET + верификация |
| **L3: Метаданные** | SNR, контекст (песня/тревога), наложения | Орнитолог | Кастомная веб-форма |
| **L4: Сегментация** | Точные границы вокализации в файле | Орнитолог + ML-инженер (авто + ручная коррекция) | Audacity + скрипты |

### 4.2. Контроль качества

- **Двойная слепая разметка:** 10% файлов размечаются двумя независимыми annotator'ами. При согласованности < 85% — пересмотр методологии.
- **Золотой стандарт:** орнитолог размечает 5% файлов как ground truth. Сравнение с junior-разметчиками — расчет Cohen's Kappa.
- **Active Learning:** модель NN1/NN3 выявляет "сомнительные" примеры (близкие к порогу решения) — они приоритетно отправляются орнитологу на проверку.

### 4.3. Методология разметки (гайдлайн для annotator'ов)

Документ на 10–15 страниц с примерами:
- Что считать "птицей" (включая крики тревоги, птенцов, ток).
- Как различать близкие виды (например, два вида пеночек).
- Как размечать наложения (если две птицы поют одновременно — помечать обе).
- Как работать с плохим качеством записи.

## 5. Аугментация данных

Цель — увеличить разнообразие без сбора новых записей.

### 5.1. Для NN1 и NN3 (классификация)

| Тип аугментации | Описание | Цель |
|-----------------|----------|------|
| **Time stretching** | Изменение скорости ×0.9...×1.1 | Имитация вариативности темпа песни |
| **Pitch shifting** | Сдвиг тона на ±2 полутона | Имитация индивидуальных различий |
| **Additive noise** | Добавление фонового шума (SNR 5...20 дБ) | Устойчивость к реальным условиям |
| **Reverberation** | Имитация эха (лес, поле, город) | Разные акустические среды |
| **Time masking** | Случайное удаление участков (SpecAugment) | Устойчивость к пропускам |
| **Frequency masking** | Случайное masking полос частот | Устойчивость к помехам |
| **Mixup** | Линейная интерполяция между двумя примерами | Регуляризация |

### 5.2. Для NN2 (source separation)

- **Синтетическое микширование** (описано в п.3.2) — основной метод.
- **Имитация АЧХ микрофона:** применение частотных фильтров, имитирующих дешевый MEMS-микрофон с дрейфом.
- **Имитация клиппинга:** обрезание пиков амплитуды (если запись была слишком громкой).

### 5.3. Запрещенные аугментации

- Нельзя менять вид птицы (pitch shifting > ±3 полутонов может превратить один вид в другой).
- Нельзя добавлять шум, который сам по себе похож на птицу (например, стрекотание насекомых в позитивный класс).

## 6. Версионирование датасетов

Датасет — это **артефакт продукта**, он должен версионироваться как код.

**Инструменты:**
- **DVC (Data Version Control)** — версионирование файлов датасета в Git-подобном стиле.
- **MLflow** — трекинг экспериментов: какой датасет → какая модель → какая метрика.
- **Metadata DB** (PostgreSQL) — для каждой записи: источник, дата, GPS, annotator, версия разметки.

**Правила:**
- Каждое изменение датасета (добавление записей, переразметка) — новая версия (v1.0, v1.1, ...).
- Запрещено удалять старые версии — только деприкейт.
- Каждая модель в продакшене привязана к конкретной версии датасета.

## 7. План сбора данных по спринтам (MVP)

| Спринт | Действия | Ответственный | Результат |
|--------|----------|---------------|-----------|
| **1–2** | Скачивание Xeno-canto, Macaulay для 50 видов региона. Фильтрация по качеству. | ML-инженер + Орнитолог | Базовый датасет v0.1 (~30k записей) |
| **1–2** | Целевой полевой сбор на пилотной локации (парabolic mic, 1 неделя). | Орнитолог | ~50 часов "эталонных" записей |
| **3–4** | Разметка L1 (бинарная) — аутсорс. Разметка L2 (видовая) — орнитолог. | Орнитолог + аутсорс | Датасет v0.2 для NN1 и NN3 |
| **3–4** | Синтетическое микширование для NN2. | ML-инженер | 100k пар (смесь, чистый сигнал) |
| **5–6** | Пилотное развертывание — сбор реальных данных с 5 датчиков. | CTO + Орнитолог | ~500 часов полевых данных |
| **7–8** | Переразметка полевых данных, добавление в датасет. Дообучение моделей. | Орнитолог + ML-инженер | Датасет v1.0 (финальный для MVP) |

## 8. Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| **Нехватка записей редких видов** (< 100 на вид) | Высокая | Высокое | Аугментация, transfer learning с крупных моделей (BirdNET), фокус на 30 самых частых видах |
| **Перекос по регионам** (модель не узнает местные диалекты) | Высокая | Критическое | Обязательный полевой сбор в регионе пилота, fine-tuning на локальных данных |
| **Низкое качество open-source записей** (шум, клиппинг) | Средняя | Среднее | Автоматическая фильтрация по SNR, ручная проверка орнитологом |
| **Ошибки разметки** (неверный вид, пропущенные наложения) | Средняя | Высокое | Двойная разметка, контроль Cohen's Kappa, active learning |
| **Domain gap между синтетикой и реальностью (NN2)** | Высокая | Высокое | Аугментация синтетики, fine-tuning на реальных данных |
| **Юридические риски** (лицензии Xeno-canto — CC BY-NC-SA) | Низкая | Среднее | Соблюдение лицензий, указание атрибуции, для коммерческого использования — прямой контакт с авторами |

## 9. Критерии готовности датасета к обучению

Датасет считается готовым, если:

1. ✅ Покрытие ≥ 90% целевых видов (≥ 45 из 50) с ≥ 300 записями на вид.
2. ✅ Баланс позитив/негатив для NN1 в пределах 0.8:1 ... 1.2:1.
3. ✅ Cohen's Kappa между annotator'ами ≥ 0.85.
4. ✅ Test set содержит ≥ 20% полевых данных, не виденных при обучении.
5. ✅ Датасет версионирован в DVC, привязан к эксперименту в MLflow.
6. ✅ Юридическая проверка: все записи имеют корректные лицензии, атрибуция готова.

## 10. Пост-MVP: масштабирование датасета

После успешного MVP и Seed-раунда:

- **Расширение до 200 видов** — сбор данных в 3–5 новых регионах.
- **Пассивный сбор** — установка 50+ датчиков генерирует ~20k часов/месяц.
- **Crowdsourcing** — интеграция с eBird, привлечение birdwatcher'ов к записям.
- **Active Learning в продакшене** — модель автоматически отбирает "сомнительные" записи для ручной проверки орнитологом → постоянное улучшение датасета.
- **Собственный датасет как актив** — уникальные полевые данные становятся барьером для конкурентов и основой для лицензирования научному сообществу.
