# Подготовка данных для разметки L1 (bird / no bird)
Версия: 1.1
Статус: Методика разметки L1, синхронизирована с MVP_SPEC/ARCHITECTURE/DATASET_STRATEGY v2.1
v1.1 — синхронизированы параметры окна анализа с единым конфигом v2.1 (2.5 сек, FFT 1024, hop 512, Hann, log-mel) и добавлены распределение фрагментов по типам dense/sparse/truncated

Разметка L1 — это бинарная классификация фрагментов «птица / не птица», которую выполняют **junior annotators** (согласно `DATASET_STRATEGY.md` п.7). Ниже — полный пошаговый процесс от сырых записей до готового датасета для обучения NN1.

---

## Этап 0. Понимание задачи L1

**Цель:** получить 100 000 размеченных окон (50k «птица» + 50k «не птица») для обучения NN1.

| Параметр | Значение | Источник |
|---|---|---|
| Классы | 2: `bird` / `no_bird` | DATASET_STRATEGY п.3 |
| Целевой объём | 50k + 50k спектрограмм | DATASET_STRATEGY п.3 |
| Баланс | 0.8:1 – 1.2:1 | DATASET_STRATEGY п.13 |
| Исполнитель | Junior annotators | DATASET_STRATEGY п.7 |
| Контроль | 10% двойная разметка, Kappa ≥ 0.85 | DATASET_STRATEGY п.8 |
| Test set | Только полевые данные | DATASET_STRATEGY п.3 |
| **Длина окна анализа** | **2.5 сек (единый конфиг с Edge)** | DATASET_STRATEGY п.3, MVP_SPEC 2.1 |
| **Hop нарезки** | **≤ длины окна (скользящая)** | DATASET_STRATEGY п.3 |
| **FFT / hop / оконная функция** | **1024 / 512 / Hann** | MVP_SPEC 2.1, ARCHITECTURE 2.1 |

## Этап 1. Сбор и приём сырых данных

### 1.1. Источники позитивов (bird)
- **Xeno-canto** — записи целевых 50 видов региона (NN1 positive + NN3).
- **Macaulay Library** — чистые сигналы.
- **Собственные полевые записи** — 4-канальные WAV с прототипов и эталонного рекордера полевой группы.

### 1.2. Источники негативов (no_bird)
- **ESC-50, UrbanSound8K, FSD50K / AudioSet** — базовые шумы.
- **Полевые hard negatives** — собираются полевой группой **целенаправленно**:
  - шелест листвы;
  - стрекотание насекомых;
  - дождь, град;
  - **ветер с разных направлений** (критично для 4-канальной системы!);
  - далёкий транспорт;
  - лягушки, грызуны;
  - пилы, моторы, антропогенные звуки.

### 1.3. Приёмка файлов
Каждый поступающий файл проверяется на:
- ✅ Читаемость (WAV не битый);
- ✅ Соответствие формату: 44.1 кГц, 16 бит, 4 канала (для полевых);
- ✅ Наличие метаданных: `device_id`, `gps`, `timestamp`, `habitat`, `license`;
- ✅ Регистрацию в базе метаданных (PostgreSQL) с присвоением `source_id`.

> ⚠️ **Важно:** на этом этапе **НЕ отфильтровывайте** «плохие» записи с ветром и шумом. Они — будущие hard negatives. Отбраковываются только технически битые файлы.

---

## Этап 2. Техническая инспекция и отбраковка

Отбраковываются записи с дефектами, делающими их непригодными для обучения:

| Дефект | Действие |
| :--- | :--- |
| Клиппинг (перегрузка) | Отбраковка |
| Отказ одного из 4 каналов (полевые) | Отбраковка или пометка `channel_fault` |
| Полный цифровой шум / артефакты записи | Отбраковка |
| Длительность < 1 сек | Отбраковка |
| Синхронные дубликаты (один файл загружен дважды) | Удаление дубликата |

**Инструменты:** автоматический скрипт (librosa/torchaudio) + выборочное прослушивание 5% выборки.

## Этап 3. Сегментация на окна разметки

NN1 работает **окнами анализа**, а не целыми файлами. Поэтому сырые записи нарезаются на фрагменты.

### 3.1. Параметры окна

⚠️ Параметры окна анализа являются **единым конфигом** для Edge-прошивки 
и обучающего датасета. Любое отклонение создаёт train/inference mismatch 
и деградирует модель в продакшене.

| Параметр | Значение | Примечание |
|---|---|---|
| Длина окна анализа | **2.5 сек** | Единая для Edge-инференса и обучающих фрагментов |
| Частота дискретизации | 44.1 кГц | Совпадает с захватом гаджета |
| FFT-окно | 1024 отсчётов (~23 мс) | Внутреннее окно спектрограммы |
| Hop спектрограммы | 512 отсчётов (~11.6 мс) | Шаг между FFT-окнами |
| Оконная функция | Hann | Фиксируется и не меняется |
| Частотный диапазон | до 22.05 кГц | Полный диапазон захвата |
| Представление | log-mel спектрограмма | Тип фиксируется в конфиге обучения |
| Hop нарезки обучающих фрагментов | ≤ 2.5 сек | Скользящая нарезка |

Правила фрагментов датасета:
- Обучающий фрагмент **строго равен 2.5 секундам**. Фрагменты иной длины 
  не допускаются в train/val/test без явного версионирования и пересборки.
- Параметры спектрограмм фрагментов идентичны параметрам, вычисляемым на Edge.
- Нарезка обучающих фрагментов выполняется **скользящим способом** (hop ≤ длины 
  окна), чтобы вокализации оказывались в разных позициях окна.

Правила позиции вокализации в окне:
- Позиция вокализации внутри фрагмента **не фиксирована** (случайная): 
  начало / середина / конец одинаково допустимы.
- Целевое распределение позитивов по типу:

| Тип позитива | Целевая доля | Описание |
|---|---|---|
| Плотный | ~40% | Вокализация заполняет окно |
| Разреженный | ~40% | Короткий крик на фоне (главный сценарий миграции) |
| Обрезанный | ~20% | Вокализация у границы окна |

Обрезанные позитивы не являются ошибкой и включаются намеренно, так как 
отражают реальное поведение окна на Edge.

### 3.2. Предварительная авто-сегментация
Для ускорения работы аннотаторов:
1. Прогнать сырые записи через energy-based детектор активности или baseline NN1 v0.1.
2. Вырезать фрагменты с активностью + контекст ±1 сек.
3. Сформировать очередь на ручную проверку.

Это **не заменяет** ручную разметку, а только сокращает объём «пустого» аудио, которое аннотатору пришлось бы слушать.

## Этап 4. Подготовка инструмента разметки

### 4.1. Рекомендуемый инструмент
**Label Studio** (с аудио-плеером + спектрограммой) или Audacity с экспортом меток.

### 4.2. Настройка задания
Каждое задание аннотатору содержит:
- Аудиофрагмент (2.5 сек);
- Спектрограмму (визуальная подсказка);
- Кнопки выбора: `bird` / `no_bird` / `unsure`;
- Поле комментария для сложных случаев;
- Поле `multi_source` (если слышно несколько источников одновременно).

### 4.3. Критично: опция «unsure»
Junior annotator **обязан** иметь возможность пометить фрагмент как `unsure`. Эти фрагменты уходят орнитологу, а не «угадываются». Это основа Active Learning (DATASET_STRATEGY п.8).

---

## Этап 5. Инструкция для junior annotators

Это самый важный документ этапа. Без него согласованность (Kappa ≥ 0.85) недостижима.

### 5.1. Правило позитива (bird)
> Фрагмент помечается `bird`, если в нём **слышна хотя бы одна птичья вокализация** (песня, крик, тревога, полётный крик, ток) на любом из каналов.

- Если птица слышна только на одном из 4 каналов — всё равно `bird`.
- Если голос очень тихий/далёкий, но различим как птичий — `bird` + пометка `low_snr`.
- Если птица слышна менее ~0.3 сек и неразличима — `unsure`.
#### Целевое распределение позитивов по типу (обязательно при сборе)

Аннотаторы и ответственный за сбор должны следить, чтобы в датасете NN1 
были представлены все три типа позитивов в целевой пропорции:

- **Плотные (song на всё окно)** ~40% — длинные песни с высоким SNR.
- **Разреженные (короткий крик на фоне)** ~40% — полётные крики, тревожные 
  сигналы длительностью 0.1–0.5 сек. **Это основной тип событий миграции.**
- **Обрезанные (крик у границы окна)** ~20% — вокализация начинается 
  или заканчивается в пределах 0.3 сек от края окна.

Если в датасете преобладают плотные позитивы, модель не научится детектировать 
короткие крики и пропустит большую часть мигрантов.

### 5.2. Правило негатива (no_bird)
> Фрагмент помечается `no_bird`, если птичьих голосов **нет вообще**, даже при наличии других звуков.

### 5.3. Типичные ловушки (обязательно в инструкцию!)

| Звук | Класс | Почему |
| :--- | :--- | :--- |
| Лягушки | `no_bird` | Частая ошибка — похожи на птиц |
| Насекомые (цикады, сверчки) | `no_bird` | Могут имитировать трели |
| Скрип деревьев, веток | `no_bird` | Похож на крики |
| Свист ветра в проводах | `no_bird` | Похож на полётный крик |
| Птица + дождь одновременно | `bird` | Птица есть — позитив |
| Несколько птиц одновременно | `bird` + `multi_source` | Пометить обязательно |
| Электронный писк гаджета | `no_bird` | Артефакт, не природа |

### 5.4. Что делать с «птица, но не видно какая»
Для L1 это **не важно**. Вид определять не нужно — только факт наличия. Видовая классификация — это L2.

## Этап 6. Процесс разметки

### 6.1. Организация работы
1. Аннотаторы получают пакеты по 200–500 фрагментов.
2. Обязательный перерыв каждые 45–60 минут (усталость уха снижает качество).
3. Прослушивание в наушниках закрытого типа, на одинаковой умеренной громкости.

### 6.2. Последовательность прослушивания
1. Прослушать фрагмент целиком.
2. При сомнении — посмотреть на спектрограмму (птичьи вокализации имеют характерную структуру: тональные свисты, трели, гармоники).
3. Принять решение: `bird` / `no_bird` / `unsure`.
4. Сложный случай — комментарий + `unsure`.

### 6.3. Контроль темпа
Норма junior-аннотатора: ~150–250 фрагментов/час при 2.5 сек окнах. Значительно более высокий темп — сигнал к проверке качества.

---

## Этап 7. Контроль качества

Согласно `DATASET_STRATEGY.md` п.8 — обязательные процедуры:

### 7.1. Двойная слепая разметка (10%)
- 10% фрагментов раздаются **двум разным** аннотаторам независимо.
- Считается согласованность. Цель: **≥ 85%**.

### 7.2. Golden Set (5%)
- 5% фрагментов заранее размечены **лично Lead Ornithologist**.
- Аннотаторы не знают, какие фрагменты входят в golden set.
- Точность каждого аннотатора на golden set — его персональная метрика.

### 7.3. Cohen's Kappa
- По результатам двойной разметки считается **Cohen's Kappa ≥ 0.85**.
- Если Kappa ниже:
  1. Остановить разметку;
  2. Провести разбор ошибок с аннотаторами;
  3. Обновить инструкцию (добавить новые ловушки);
  4. Переразметить спорную партию.

### 7.4. Разрешение конфликтов
Если два аннотатора разошлись во мнении:
1. Фрагмент уходит **орнитологу** как арбитру.
2. Решение орнитолога — финальное.
3. Все арбитрованные случаи добавляются в обновлённую инструкцию как примеры.

### 7.5. Обработка `unsure`
- Все `unsure` уходят орнитологу (Active Learning).
- После решения орнитолога фрагмент возвращается в датасет с меткой.
- Доля `unsure` > 15% — сигнал, что инструкция или датасет слишком «шумные».

## Этап 8. Формирование финального датасета L1

### 8.1. Балансировка
- Целевой баланс: 50k `bird` + 50k `no_bird` (допустимо 0.8:1 – 1.2:1).
- Если негативов больше (обычно так и есть, т.к. hard negatives собираются целенаправленно) — **не удалять**, а сохранить в резервный пул для дообучения.

### 8.2. Разделение Train / Val / Test
| Split | Доля | Состав |
| :--- | :--- | :--- |
| Train | 70% | open-source + полевые |
| Val | 15% | open-source + полевые |
| **Test** | **15%** | **ТОЛЬКО полевые данные** |

> ⚠️ **Критично:** Test set не должен пересекаться с Train/Val ни по одному фрагменту. Утечка данных из Test в Train invalidates все метрики MVP.

### 8.3. Стратификация разделения
При разбиении учитывать, чтобы не было перекосов по:
- биотопу;
- типу шума (не все hard negatives только в Test);
- времени суток;
- устройству записи.

## Этап 9. Версионирование и хранение

Согласно `DATASET_STRATEGY.md` п.10:

### 9.1. Инструменты
- **DVC** — версионирование аудио и размеченных данных;
- **MLflow** — связь модели с версией датасета;
- **PostgreSQL metadata DB** — метаданные каждой записи.

### 9.2. Для каждого фрагмента хранить
```yaml
sample_id: "uuid"
audio_path: "..."
channel_layout: "N/E/S/W"   # или "mono_mix"
label: "bird" | "no_bird"
label_level: "L1"
annotator: "junior_003"
verified_by: "ornithologist"  # если был конфликт/unsure
confidence: "high" | "low_snr" | "multi_source"
source: "xeno-canto" | "field_proto-001" | "esc-50"
license: "CC-BY-NC-4.0"
date: "2026-08-16"
gps: {...}                    # если полевые
dataset_version: "v0.1"
audio_window_config:
  window_length_s: 2.5
  fft_size: 1024
  hop_size: 512
  window_function: "hann"
  sample_rate: 44100
  representation: "log-mel"
fragment_type: "dense" | "sparse" | "truncated"   # только для позитивов NN1
```

### 9.3. Правила
- Каждое изменение датасета = **новая версия** (v0.1 → v0.2 → v1.0).
- Старые версии **не удаляются**.
- Модель NN1 привязывается к конкретной версии датасета.

## Этап 10. Передача в ML-пайплайн

После завершения разметки датасет передаётся ML-инженеру для обучения NN1:

1. **Спектрограммы генерируются в облаке/ML-пайплайне** из сырых WAV (с едиными параметрами FFT/hop) — не на edge-гаджете.
2. **Проверка соответствия параметров окна (обязательно).**
   ML-инженер сверяет параметры спектрограмм датасета с единым конфигом 
   Edge-прошивки (`DATASET_STRATEGY.md` п.3, `MVP_SPEC.md` п.2.1, 
   `ARCHITECTURE.md` п.2). При любом несоответствии датасет отклоняется, 
   создаётся новая версия датасета с корректными параметрами.
3. Применяются аугментации для NN1 (`DATASET_STRATEGY.md` п.9):
   - time stretching;
   - pitch shifting **до ±2 полутонов** (запрещено > ±3!);
   - additive noise;
   - reverberation;
   - time / frequency masking (SpecAugment);
   - mixup.
4. **Запрещено:** добавление насекомого шума в позитивный класс (создаёт ложные корреляции).

## Чек-лист готовности датасета L1

Перед передачей в обучение NN1 убедиться:

- [ ] 50k bird + 50k no_bird размечено (баланс 0.8:1 – 1.2:1)
- [ ] 10% фрагментов прошли двойную разметку, согласованность ≥ 85%
- [ ] Cohen's Kappa ≥ 0.85
- [ ] 5% golden set размечен орнитологом
- [ ] Все `unsure` разрешены орнитологом
- [ ] Test set = 15% и содержит **только полевые данные**
- [ ] Нет пересечений между Train/Val/Test
- [ ] Hard negatives покрывают: ветер с разных направлений, насекомых, дождь, транспорт, лягушек, грызунов, пилы/моторы
- [ ] Датасет версионирован (DVC + MLflow + PostgreSQL)
- [ ] Лицензии всех источников проверены
- [ ] Инструкция аннотаторов задокументирована и версионирована
- [ ] Длина каждого обучающего фрагмента **ровно 2.5 сек** (единый конфиг с Edge)
- [ ] Параметры спектрограмм (FFT 1024, hop 512, Hann, 44.1 кГц, log-mel) 
      идентичны параметрам Edge-прошивки
- [ ] Распределение позитивов по типу (dense ~40% / sparse ~40% / truncated ~20%) 
      соответствует целевому
- [ ] У каждого фрагмента сохранён атрибут `audio_window_config` 
      и `fragment_type` (для позитивов)
- [ ] ML-инженер подтвердил соответствие параметров окна единому конфигу 
      перед передачей в обучение

## Резюме процесса

Сырые WAV (open-source + полевые)
  → Приёмка + регистрация в БД
  → Техническая отбраковка
  → Нарезка на окна 2.5 сек
  → Подготовка Label Studio + инструкции
  → Разметка junior annotators (bird/no_bird/unsure)
  → Контроль качества (10% двойная, 5% golden set, Kappa ≥ 0.85)
  → Арбитраж орнитолога для конфликтов и unsure
  → Балансировка 50k/50k
  → Split 70/15/15 (Test — только полевые)
  → Версионирование (DVC + MLflow + PostgreSQL)
  → Передача ML-инженеру для NN1

Главный принцип этапа L1: **скорость junior-аннотаторов + жёсткий контроль качества орнитологом**. Именно связка «дешёвая массовая разметка + golden set + Kappa-контроль» позволяет набрать 100k образцов без потери качества, требуемого для F1 ≥ 0.90 у NN1.
