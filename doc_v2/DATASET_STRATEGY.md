# Стратегия сбора и разметки данных

Версия: 2.1
v2.1 — зафиксированы параметры окна анализа NN1 и распределение ответственности
Статус: MVP с 4 микрофонами, направлением источника и трекингом

---

## 1. Общие принципы

Качество системы определяется не только распознаванием видов, но и корректностью:

- детекции птиц;
- направления источника;
- классификации вида;
- open-set решений;
- вероятностных треков;
- миграционных карт.

Принципы:

1. Репрезентативность региона.
2. Покрытие сезонов и времени суток.
3. Покрытие биотопов.
4. Покрытие шумовых условий.
5. Покрытие направлений источников.
6. Баланс классов.
7. Валидация орнитологом.
8. Версионирование датасетов.

Ответственные:

- орнитолог — методология и контроль качества;
- ML-инженер — пайплайн данных, аугментация, обучение;
- CEO — доступ к полевым данным и партнерам.

## 3. Датасет для NN1

### Задача

Бинарная классификация: птица / не птица.

### Особенности обновленного датасета

- данные должны быть совместимы с 4-канальным входом;
- допускается обучение на агрегированных признаках;
- необходимо включать направленные шумы;
- необходимо включать ветер, дующий с разных направлений;
- необходимо включать насекомых, воду, транспорт.

### Параметры окна анализа и фрагментов данных

Параметры окна анализа являются единым конфигом для Edge-прошивки и обучающего
пайплайна. Датасет и прошивка обязаны использовать идентичные значения,
иначе возникает train/inference mismatch.

| Параметр | Значение | Примечание |
| --- | --- | --- |
| Длина окна анализа | 2.5 сек | Единая для Edge-инференса и обучающих фрагментов |
| Частота дискретизации | 44.1 кГц | Совпадает с захватом гаджета |
| FFT-окно | 1024 отсчётов (~23 мс) | Внутреннее окно спектрограммы |
| Hop спектрограммы | 512 отсчётов (~11.6 мс) | Шаг между FFT-окнами |
| Оконная функция | Hann | Фиксируется и не меняется |
| Частотный диапазон | до 22.05 кГц | Полный диапазон захвата |
| Представление | log-mel / mel-спектрограмма | Тип фиксируется в конфиге обучения |
| Hop инференса (базовый) | 1.0 сек | Шаг скольжения окна на Edge |
| Hop инференса (adaptive) | 2.0 сек | При деградации батареи |
| Hop инференса (высокая чувствительность) | 0.5 сек | Пиковые часы миграции |
| Pre-roll | ≥ 2 сек | Из MVP_SPEC |
| Длительность WAV-события | 10 сек | Из MVP_SPEC |

Правила фрагментов датасета:

- Обучающий фрагмент равен длине окна анализа (2.5 сек). Фрагменты иной длины
  не допускаются в train/val/test без явного версионирования.
- Параметры спектрограммы фрагментов датасета идентичны параметрам,
  вычисляемым на Edge.
- Hop нарезки обучающих фрагментов ≤ длины окна (скользящая нарезка),
  чтобы вокализации оказывались в разных позициях окна.

Правила позиции вокализации в окне:

- Позиция вокализации внутри фрагмента не фиксирована (случайная):
  начало / середина / конец одинаково допустимы.
- Целевое распределение позитивов по типу:
  | Тип позитива | Целевая доля |
  | --- | --- |
  | Плотный (вокализация заполняет окно) | ~40% |
  | Разреженный (короткий крик на фоне) | ~40% |
  | Обрезанный (вокализация у границы окна) | ~20% |
- Обрезанные позитивы не являются ошибкой и включаются намеренно,
  так как отражают реальное поведение окна на Edge.
  
### Целевой баланс

| Класс | Объем |
|---|---|
| Птица | 50k спектрограмм |
| Не птица | 50k спектрограмм |

### Hard negatives

- шелест листвы;
- стрекотание насекомых;
- дождь;
- град;
- ветер в разных направлениях;
- далекий транспорт;
- лягушки;
- грызуны;
- пилы;
- моторы;
- антропогенные звуки.

### Разделение

- Train: 70%; Val: 15%; Test: 15%.
- Test set должен содержать только полевые данные.

## 4. Датасет для модуля направления (DOA)

Это новый критический датасет для MVP.

### Задача

Разметка направления источника звука относительно датчика.

### Типы разметки

- сектор: N / NE / E / SE / S / SW / W / NW;
- азимут: 0–360°;
- уверенность;
- качество записи;
- один источник / несколько источников;
- движущийся / стационарный источник.

### Источники

1. Стендовые записи:
   - источник звука на известном азимуте;
   - расстояния 5, 10, 20, 50 м;
   - разные высоты;
   - разные типы сигналов.

2. Полевые записи:
   - орнитолог фиксирует направление;
   - несколько наблюдателей;
   - параллельная видеосъемка при возможности;
   - записи движущихся птиц.

3. Синтетическая аугментация:
   - имитация межканальных различий;
   - изменение уровня каналов;
   - изменение SNR;
   - направленный ветер;
   - отражения.

### Целевой объем

- ≥ 20k событий с известным направлением;
- ≥ 5k движущихся последовательностей;
- ≥ 30% данных — полевые;
- ≥ 10% данных — сложные условия.

### Метрики

- MAE азимута;
- sector accuracy;
- confidence calibration;
- доля ambiguous случаев;
- качество на низком SNR.

## 5. Датасет для NN2

### Задача

Разделение целевого голоса птицы и фона.

### Обновленные требования

- синтетические смеси должны учитывать направленные шумы;
- желательно создавать многоканальные версии смесей;
- необходимо имитировать АЧХ 4 MEMS-микрофонов;
- необходимо включать dawn chorus.

### Структура

- чистые голоса птиц;
- фоновые шумы;
- пары `(смесь, чистый сигнал)`;
- SNR от -10 дБ до +10 дБ;
- 20+ типов фонов;
- 100k синтетических смесей.

### Domain gap mitigation

- реверберация;
- имитация дешевого микрофона;
- клиппинг;
- ветер;
- тонкие спектральные искажения;
- fine-tuning на реальных полевых данных.

## 6. Датасет для NN3

### Задача

Классификация 50 видов региона пилота + Unknown.

### Требования

- ≥ 500 записей на вид суммарно;
- покрытие региональных диалектов;
- покрытие сезонов;
- покрытие времени суток;
- покрытие типов вокализаций: песня, тревога, полетный крик, ток, крики птенцов.

### Unknown classes

- 200+ видов вне региона пилота;
- 50+ классов не птичьих звуков;
- используются для Open-Set training.

### Open-Set метод

- ArcFace / Angular Softmax;
- Outlier Exposure;
- порог Unknown калибруется на валидации;
- цель: отбрасывать ≥ 70% неизвестных звуков.

## 7. Уровни разметки

| Уровень | Описание | Ответственный |
|---|---|---|
| L1 | bird / no bird | junior annotators |
| L2 | вид | орнитолог / trained annotator |
| L3 | метаданные, SNR, контекст | орнитолог |
| L4 | границы вокализации | орнитолог + ML |
| L5 | направление источника | орнитолог + полевой инженер |
| L6 | трек / последовательность / движение | орнитолог + ML |

---

## 8. Контроль качества

- 10% файлов размечаются двумя annotators.
- согласованность ≥ 85%.
- 5% golden set размечает орнитолог.
- Cohen's Kappa ≥ 0.85.
- Active Learning для сомнительных примеров.
- Обязательная проверка Unknown.
- Обязательная проверка low confidence bearings.

## 9. Аугментация данных

### Для NN1 и NN3

- time stretching;
- pitch shifting до ±2 полутонов;
- additive noise;
- reverberation;
- time masking;
- frequency masking;
- mixup.

### Для направления

- изменение уровня каналов N/E/S/W;
- имитация задержек между каналами;
- направленный ветер;
- отражения;
- изменение ориентации датчика;
- имитация дрейфа одного канала;
- симуляция движения источника.

### Для NN2

- синтетическое микширование;
- имитация MEMS АЧХ;
- клиппинг;
- многоканальные смеси.

### Запрещено

- pitch shifting более ±3 полутонов;
- добавление насекомого шума в позитивный класс;
- изменение направления без корректной канальной симуляции;
- создание ложных треков из несвязанных событий.
- изменение длины окна анализа или параметров спектрограммы (FFT, hop, оконная
  функция) относительно единого конфига без создания новой версии датасета
  и прошивки;
- аугментация, нарушающая синхронизацию параметров фрагментов датасета
  и Edge-инференса.

## 10. Версионирование

Инструменты:

- DVC;
- MLflow;
- PostgreSQL metadata DB.

Для каждой записи хранить:

- source;
- license;
- date;
- GPS;
- device_id;
- channel layout;
- annotator;
- annotation version;
- direction label;
- track label;
- quality flags.
- audio window config (длина окна, FFT, hop, оконная функция, sample rate);
- fragment type (dense / sparse / truncated) для позитивов NN1.

Правила:

- каждое изменение датасета — новая версия;
- старые версии не удаляются;
- модель привязывается к версии датасета.

## 12. Риски

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Мало данных с направлением | Высокая | Высокое | Стендовые записи, симуляция, полевая разметка |
| Ошибки ориентации датчика | Средняя | Высокое | Калибровка, метаданные, проверка |
| Ветер ломает пеленг | Высокая | Высокое | SNR-фильтры, directional hard negatives |
| Несколько источников | Высокая | Среднее | multi_source flag, NN2, ручная проверка |
| Мало редких видов | Высокая | Высокое | transfer learning, фокус на частых видах |
| Domain gap NN2 | Высокая | Высокое | fine-tuning, аугментация |
| Лицензии | Низкая | Среднее | юридическая проверка, атрибуция |

## 13. Критерии готовности датасета

Датасет считается готовым, если:

- ≥ 90% целевых видов имеют ≥ 300 записей;
- баланс NN1 в пределах 0.8:1–1.2:1;
- Cohen's Kappa ≥ 0.85;
- Test set содержит ≥ 20% полевых данных;
- direction test set содержит полевые записи;
- есть не менее 1000 размеченных последовательностей для трекинга;
- датасет версионирован;
- лицензии проверены.
- параметры окна анализа и спектрограмм датасета (длина окна, FFT, hop,
  оконная функция, частота дискретизации) идентичны параметрам Edge-прошивки;
- распределение позитивов по типу (плотный / разреженный / обрезанный)
  соответствует целевому;
- все фрагменты датасета равны длине окна анализа.
