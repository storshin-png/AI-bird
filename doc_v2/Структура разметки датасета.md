# Структура разметки датасета для NN1 и NN3

Документ описывает единую структуру манифеста, уровни разметки, правила и контроль качества для двух моделей: **NN1** (детектор bird/no_bird) и **NN3** (классификатор видов).

---

## 1. Единый манифест `manifest_fragments.csv`

Один CSV-файл обслуживает обе модели. Разметка идёт **итеративно**: сначала L1 (NN1), затем L2-L3 (NN3) для позитивов NN1.

| Колонка | Тип | Источник | Описание |

| `source_file` | str | `cut_fragments.py` | Имя исходника без расширения |
| `start_ms` | int | `cut_fragments.py` | Позиция начала фрагмента в исходнике, мс |
| `duration_sec` | float | `cut_fragments.py` | Всегда `2.5` (единый конфиг) |
| `rms` | float | `cut_fragments.py` | RMS амплитуда (для отсечения тишины) |

## 2. Разметка L1 для NN1 (bird / no_bird)

### 2.1. Правило разметки

> **«Есть ли в этом окне 2.5 с голос птицы?»**

- `bird` — слышен хотя бы один птичий голос (песня, крик, эхо, позывка)
- `no_bird` — только шум, насекомые, ветер, транспорт, лягушки, тишина
- `unsure` — сомнение, передаётся орнитологу на арбитраж

### 2.2. Тип позитива `fragment_type`

| Тип | Определение | Целевая доля |
|---|---|---|
| `dense` | Вокализация заполняет большую часть окна (>60%) | ~40% |
| `sparse` | Короткий крик/позывка на фоне (<40% окна) | ~40% |
| `truncated` | Вокализация у границы окна (начало или конец) | ~20% |

### 2.3. Правила для спорных случаев

| Сценарий | Метка | Тип | Пояснение |
|---|---|---|---|
| Слышно только эхо | `bird` | `truncated` | Эхо = отражение сигнала птицы |
| Крик + обрезанное эхо | `bird` | `truncated` | Реальный сценарий на границе окна |
| Отрывистое карканье ворона | `bird` | `dense` или `truncated` | Карканье = голос птицы |
| Пролетающая птица (тихо → громко → тихо) | `bird` | `dense` / `truncated` | Слышна хотя бы частично = `bird` |
| Непрерывная песня на соседних окнах | `bird` | Каждое окно независимо | Не объединять в одно событие |
| Насекомое + птица одновременно | `bird` | `sparse` или `dense` | Птица есть → `bird` |
| Сомнение (тихо, непонятно) | `unsure` | — | Передаётся орнитологу |

### 2.4. Запрещено при разметке L1

- ❌ Классифицировать тип вокализации (это задача NN3)
- ❌ Исключать эхо как артефакт
- ❌ Менять метку из-за громкости
- ❌ Размечать соседние фрагменты как одно событие
- ❌ Создавать «ложные» негативы из тихих птиц

## 3. Разметка L2-L3 для NN3 (классификация видов)

### 3.1. Область разметки

Разметка L2-L3 выполняется **только для фрагментов с `label == "bird"`**. Для `no_bird` и `unsure` эти колонки остаются пустыми.

### 3.2. Правило определения вида

> **«Какой вид птицы издал этот звук?»**

- Конкретный вид — латинское название (например, `Turdus merula`)
- `unknown` — птица есть, но вид определить невозможно
- `""` (пусто) — разметка ещё не выполнена

### 3.3. Типы вокализаций

| Тип | Описание | Пример |
|---|---|---|
| `song` | Типичная песня (территориальная, брачная) | Пение соловья |
| `call` | Короткий контактный крик | Позывка синицы |
| `alarm` | Тревожный крик | Алярный крик дроздов |
| `flight` | Полётный крик | Крик гусей в стае |
| `begging` | Крик птенца | Выпрашивание корма |
| `duet` | Дуэт двух птиц | Перекличка |
| `unknown` | Тип не определён | — |

### 3.4. Оценка SNR

| SNR | Качество | Комментарий |
|---|---|---|
| > 15 дБ | Отличное | Чистый сигнал |
| 5–15 дБ | Хорошее | Сигнал слышен на фоне шума |
| 0–5 дБ | Среднее | Сигнал на грани слышимости |
| < 0 дБ | Плохое | Сигнал почти не различим |

### 3.5. Множественные источники

| `num_sources` | Описание | Действие |
|---|---|---|
| 1 | Один источник | Разметить вид основного источника |
| 2 | Два источника | Разметить вид **доминирующего** источника |
| 3+ | Несколько источников | Разметить доминирующий + флаг `multi_source` |

> **Важно:** NN2 (source separation) будет разделять источники. В датасете NN3 размечаем **доминирующий** голос.

### 3.6. Движение источника

| `source_motion` | Описание |
|---|---|
| `stationary` | Птица поёт с одного места |
| `approaching` | Приближается (громкость растёт) |
| `receding` | Удаляется (громкость падает) |
| `flying_over` | Пролетает над датчиком |
| `unknown` | Не определено |

## 5. Связь между датасетами NN1 и NN3

```
┌─────────────────────────────────────────────────────────────┐
│                  ЕДИНЫЙ МАНИФЕСТ                            │
│              manifest_fragments.csv                         │
├─────────────────────────────────────────────────────────────┤
│  Все фрагменты: 100k                                        │
│  ├── bird (50k) ──────→ NN1 POSITIVE                        │
│  │   ├── с species ───→ NN3 TRAIN (50 видов + unknown)      │
│  │   └── unknown ─────→ NN3 OPEN-SET (outlier exposure)     │
│  └── no_bird (50k) ───→ NN1 NEGATIVE                        │
│      └── hard negatives (насекомые, ветер, транспорт)       │
└─────────────────────────────────────────────────────────────┘
```

### Фильтры для обучения

**NN1** использует все фрагменты с `label ∈ {bird, no_bird}`:
```python
nn1_df = df[df["label"].isin(["bird", "no_bird"])]
```

**NN3** использует только позитивы NN1 с известным видом:
```python
nn3_df = df[(df["label"] == "bird") & (df["species"].notna()) & (df["species"] != "")]
```

**Open-Set** использует позитивы NN1 с `species == "unknown"` + специальные outlier-классы:
```python
open_set_df = df[(df["label"] == "bird") & (df["species"] == "unknown")]
```

## 6. Контроль качества разметки

### 6.1. Двойная разметка (10% файлов)

- 10% случайных файлов размечаются **двумя независимыми аннотаторами**
- Рассчитывается **Cohen's Kappa** ≥ 0.85 (целевой показатель)
- При Kappa < 0.85 → пересмотр инструкций, дообучение аннотаторов

### 6.2. Golden set (5% файлов)

- 5% файлов размечает **только орнитолог** (эталонная разметка)
- Используется для контроля точности junior annotators
- Расхождение с golden set > 15% → аннотатор отстраняется от проекта

### 6.3. Арбитраж сомнительных случаев

- Все фрагменты с `label == "unsure"` передаются орнитологу
- Орнитолог принимает окончательное решение: `bird` / `no_bird`
- Спорные случаи добавляются в **golden set** для будущих аннотаторов

### 6.4. Active Learning

- Модель NN1 на валдиации выделяет примеры с низкой уверенностью (0.3–0.7)
- Эти примеры передаются орнитологу на проверку
- Размеченные примеры возвращаются в датасет

## 7. Версионирование

Каждое изменение разметки порождает новую версию:

| Версия | Описание |
|---|---|
| `v0.1` | Первичная разметка L1 (NN1) |
| `v0.2` | Добавлена разметка L2 (виды) для 50 видов |
| `v0.3` | Добавлены метаданные L3 (SNR, motion, habitat) |
| `v0.4` | Добавлены полевые данные с L5 (направления) |
| `v1.0` | Финальная разметка после арбитража и active learning |

Правила:
- Старые версии **не удаляются**
- Модель привязывается к версии датасета (в MLflow)
- Любое изменение конфига окна анализа → новая версия датасета

## 9. Чеклист готовности датасета к обучению

### Для NN1:
- [ ] Все фрагменты размечены (нет пустых `label`)
- [ ] Баланс bird/no_bird в пределах 0.8:1–1.2:1
- [ ] Распределение типов позитивов: dense ~40%, sparse ~40%, truncated ~20%
- [ ] Cohen's Kappa ≥ 0.85
- [ ] Test set содержит только полевые данные (≥ 20% от общего объёма)
- [ ] Все фрагменты = 2.5 с (единый конфиг)

### Для NN3:
- [ ] ≥ 90% целевых видов имеют ≥ 300 записей
- [ ] Покрытие типов вокализаций (song, call, alarm, flight)
- [ ] Покрытие сезонов и времени суток
- [ ] Есть класс `unknown` для Open-Set
- [ ] Разметка L2 выполнена орнитологом или trained annotator
- [ ] Метаданные L3 заполнены для ≥ 80% позитивов
