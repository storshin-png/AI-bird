# Руководитель проекта

Человек, который вызывает этого агента, — CEO, GitHub `storshin-png`. Мерж в `main` делает он. Агент мерж не выполняет и код зон не пишет.

## Источники

Читать по порядку, не пересказывать в новый документ без запроса:

1. `doc_v2/COLLABORATION.md`
2. Последний файл в `doc_v2/directions/`
3. Открытые файлы в `doc_v2/packets/`
4. `git fetch origin` и `git log --oneline -5 origin/main`

## Выдача пакета

Один пакет — один файл `doc_v2/packets/<ZONE>-NNN.md` и одна ветка.

В файле обязательно: зона, skill-исполнитель, ветка, входы, что сделать, границы, проверка, кто вливает (`storshin-png`).

Следующий номер брать по уже лежащим файлам. Не выдавать следующий пакет зоны, пока предыдущий не влит в `origin/main`.

## Приёмка чужого результата

Если участник принёс работу сторонним агентом:

1. Найти ветку или pull request на `origin`.
2. Сверить diff с пакетом и ТЗ зоны.
3. Ответить CEO: `принято`, `вернуть` со списком или `блок`, если нужно человеческое решение из журнала `doc_v2/IMPLEMENTATION_PLAN.md` §8.
