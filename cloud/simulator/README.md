# simulator

Генератор синтетических событий. Делает то, что позже будет делать датчик: создаёт `event_id`, направление на источник, локальные треки, пакеты MQTT и 4-канальный WAV. Нужен для стенда и сквозного сценария, пока нет плат (`doc_v2/roles/04_BACKEND.md`, подготовка: «генератор кладёт телеметрию и 4-канальный WAV»).

## Что генерируется

- **Датчики** `sim-001`, `sim-002`, … в окрестностях Магнитогорска (локация пилота), каждый со своим поворотом корпуса.
- **Локальные треки** — как в `USERFLOW.md` §5.6: 3–5 детекций подряд с шагом 2–4 с, пеленг смещается на 4–9° в одну сторону, общий `track_id`.
- **Одиночные события** без `track_id`.
- **Пакеты MQTT** по `backend/docs/MQTT_PAYLOADS.md`: heartbeat на датчик, затем на каждое событие — `event` с направлением и `telemetry`.
- **WAV** события: 4 канала N, E, S, W, 16 бит, частота, длина и pre-roll из `config/window_config.yaml` (сейчас 44,1 кГц, 10 с, 2 с). До конца pre-roll — только фон, потом птичья трель. Канал, обращённый к источнику, громче и раньше остальных. Имя — как в `USERFLOW.md` §5.5: `2026-10-25_03-15-27_sim-001_evt-<event_id>.wav`.
- **Манифест** `events.jsonl` — истинный азимут каждого события, поворот корпуса и трек. Это эталон для проверки Direction QA и трекинга в следующих спринтах.

Один и тот же `--seed` даёт те же `event_id`, азимуты и WAV, поэтому прогон можно повторить, и backend посчитает всё дубликатами.

## Запуск

Из каталога `cloud/` с активным окружением (зависимости — `backend/requirements.txt`).

Стенд, миграции и `python -m backend mqtt` запущены — завести датчики и отправить события:

```text
python -m simulator --register --mqtt 127.0.0.1:1883
```

Больше событий, без WAV:

```text
python -m simulator --register --mqtt 127.0.0.1:1883 --devices 3 --tracks 5 --singles 10 --no-wav
```

Только файлы, как выгрузка SD-карты:

```text
python -m simulator --out sd_card --seed 7
```

По умолчанию файлы ложатся в `simulator/out/`, эта папка в git не попадает. Один WAV пишется около секунды.

## Параметры

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `--devices` | 2 | Сколько датчиков |
| `--tracks` | 3 | Локальных треков по 3–5 детекций |
| `--singles` | 4 | Одиночных событий |
| `--seed` | случайный, печатается | Повторяемость |
| `--prefix` | `sim` | Начало `device_id` |
| `--start` | час назад | Время первого события, ISO 8601 с поясом |
| `--out` | `simulator/out` | Папка для WAV и `events.jsonl` |
| `--no-wav` | — | Без WAV |
| `--mqtt` | — | `host:port` брокера; без него пакеты не отправляются |
| `--topic-prefix` | `birdnet` | |
| `--register` | — | Завести датчики в БД (`AIBIRD_DATABASE_URL` или стенд) |
| `--database-url` | — | Другая БД для `--register` |
| `--delay` | 0 | Пауза между событиями при отправке, секунды |

## Что модель не учитывает

Задержки между каналами посчитаны для радиуса 3 см между центром корпуса и микрофоном: размеров корпуса в репозитории пока нет. Усиление по направлению — кардиоида. Этого хватает, чтобы громкий канал совпадал с сектором и чтобы проверять приём, хранение и карту. Для обучения DOA нужен стенд из `hardware/STAND.md`.
